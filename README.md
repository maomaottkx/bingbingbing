# aim2027 · 2027 赛季征途 Uprising 视觉组考核（自瞄方向）

离线视频评测。输入一段第一视角视频，输出：红色装甲板的四个角点与中心点、装甲板中心在相机坐标系下的三维位置、每帧处理耗时。

纯 OpenCV 传统视觉，**不使用任何深度学习模型**。

> 考核要求与本项目实现的逐条对照见 [`docs/需求对照.md`](docs/需求对照.md)（含未实现项与原因）。

## 5. 参数说明

| 参数 | 含义 | 默认值 | 必填 |
|---|---|---|---|
| 第一个位置参数 | **输入视频**路径 | — | 是 |
| `--camera <路径>` | **相机参数**。读考核包的 `calibration/intrinsics.yaml`（`camera_matrix` 9 个数、`distort_coeffs` 5 个数）。不给则用 `include/config.hpp` 里内嵌的同一组标定值 | 内嵌标定值 | 否 |
| `--mask or\|and\|diff` | **目标颜色**的掩膜方式。当前实现固定检测**红色**：HSV 红色两段 ∪ 通道差 `R−max(G,B)>40`（`or`）、取交集（`and`）、只用通道差（`diff`） | `or` | 否 |
| `--save <路径>` | **输出路径**。把检测结果画在画面上写成视频（`.mp4`/`.avi`） | 不写 | 否 |
| `--out-fps <N>` | 输出视频帧率 | 跟原视频一致 | 否 |
| `--scale <倍数>` | 输出视频缩放 | `1.0` | 否 |
| `--frame <N>` | 只处理第 N 帧，打印详细结果（灯条、候选、角点、位姿） | — | 否 |
| `--limit <N>` | 只处理前 N 帧 | 全部 | 否 |
| `--compare` | 左右分屏：左=逐帧实测、右=跟踪结果 | 关 | 否 |
| `--no-tracker` | 关掉跟踪器，只看逐帧检测 | 关 | 否 |
| `--trace` | 每帧一行 CSV 输出到 stdout，便于分析 | 关 | 否 |
| `--debug` | 叠加灯条框、候选框、掩膜缩略图 | 关 | 否 |
| `--snapshot <路径>` | 存单帧 PNG | — | 否 |
| `--no-show` / `--quiet` | 不弹窗 / 不打印进度 | — | 否 |

**目标颜色**：本实现检测**红色**装甲板（考核两段视频中的目标均为红方）。蓝色未实现，原因与扩展方式见第 10 节。

## 7. 算法流程

```
读帧
 └─ 颜色掩膜：HSV 红色两段 [0,12]/[165,180] ∪ 通道差 R−max(G,B)>40，开 3×3 + 闭 3×9
     └─ findContours → 每个轮廓 minAreaRect → 灯条筛选
        （长宽比≥1.5、长≥25px、面积≥100、倾角≤45°、平均色 R−G≥55 且 R−B≥60）
         └─ 两两配对（长度差≤35%、中心距比∈[0.8,4.5]、连线斜率≤0.35、倾角差≤20°）+ 打分排序
             └─ 每块候选 solvePnP(SOLVEPNP_IPPE)，两个解按"朝向相机 + 与上一帧接近"择一
                 └─ 三重门槛：重投影≤6px、距离∈[0.5,3.5]m、|yaw|≤70°、|pitch|≤45°
                     └─ 打分选板：重投影 + 0.004×离上一帧的距离(mm)
                         └─ 四状态跟踪器 + 6 状态匀速卡尔曼（外推 + 新息检验）
                             └─ 绘制
```

关键判据的取值依据都来自本机视频实测，不是拍脑袋：

| 判据 | 取值 | 实测依据 |
|---|---|---|
| 重投影 | ≤ 6 px | 门槛 2px 时旋转场景检出只有 67%；4px→85%、6px→90%+、8px 基本饱和 |
| 灯条 R−G / R−B | ≥55 / ≥60 | 真灯条 64~73 / 74~103；窗外暖白光带 43 / 79 |
| 跟踪确认 / 保持 | 5 帧 / 15 帧 | 取自考核包 `source_demo.yaml` 的 `min_detect_count` / `max_temp_lost_count` |
| 卡尔曼新息门限 | 马氏距离² ≤ 40 | 按实测位置噪声 σ≈50 mm 标定 |

## 8. 实测结果

本机 Ubuntu 22.04 / OpenCV 4.5.4，1440×1080。**统计口径分三档**，"几何门通过"不等于"跟踪器接受"：

| 指标 | 视频1（1770 帧，装甲板转动） | 视频2（1240 帧，正对） |
|---|---|---|
| 几何门通过帧（检测出候选并通过 PnP 门槛） | 1594（90.06 %） | 1097（88.47 %） |
| 跟踪器接受帧（真正用于修正的测量） | 1530（86.44 %） | 1097（88.47 %） |
| 框显示总帧（实测 + 预测） | 1636（92.43 %） | 1104（89.03 %） |
| 框消失次数（闪烁） | 4 | 0 |
| 最长连续无框 | 40 帧 | 136 帧 |
| 假阳（框落在画面上半屏，那里只有窗户） | 0 | 0 |
| 位置跳变 中位 / 90% 分位 / 最大 | 7.5 / 34.2 / 333 mm | 4.9 / 34.8 / 104 mm |
| 单帧耗时 中位 | 16.6 ms | 16.4 ms |

单帧样例（视频1 第 300 帧）：

```
位置 x=-73.3 y=146.6 z=1821.8 mm  距离=1829.2 mm
yaw=-3.715°  pitch=16.892°  重投影=0.4004 px
```

> 耗时随虚拟机负载波动明显（同一份代码在 10~70 ms/帧之间都出现过），上表取安静环境下的中位数。

## 12. 已知限制

1. **只做红色**。考核要求是"检测指定颜色（红蓝色）的装甲板"，两段考核视频中的目标均为红方。蓝色只需把 `buildRedMask` 的 H 段与通道差换成 `B−max(R,G)`，其余流程全部复用。
2. **装甲板尺寸按考核文档取值**：宽 135 mm、高 56 mm（高度取灯条长度），对应半宽 67.5 mm、半高 28.0 mm。若实际灯条可见发光区比标称短，距离绝对值会有数个百分点的系统偏差，但同一段视频内部的相对变化不受影响。
3. **左右倾斜超过约 45°** 时四个角点的顺序会翻转，PnP 解会跳；本实现靠重投影门槛把这类解剔除（表现为丢检，不会给出错位置）。
4. **yaw/pitch 存在共面四点的镜像歧义**。4 点解平面位姿，IPPE 会给出两个重投影几乎等价的解，姿态角可差十几度。本实现用帧间连续性锁定同一支路；**位置（xyz）不受该歧义影响**。
5. **板子转到接近侧向时只剩一根灯条可见**，四点凑不齐，只能靠跟踪器保持（最长 15 帧）；这段时间显示的是橙色虚线预测框，不是实测。
6. 窗外暖白光带靠红纯度（R−G ≥ 55）剔除；换到色温更低的场地需要重新标定这个阈值。
7. 处理耗时在虚拟机里波动可达数倍，真实性能以裸机为准。
