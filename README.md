# aim2027 · 装甲板识别与测距（2027 赛季征途 Uprising 视觉组考核）

纯 OpenCV 传统视觉，**不用任何深度学习 / YOLO**。输入一段第一视角视频，输出：

1. 红色装甲板的 **4 个角点 + 中心点**，画在画面上；
2. 装甲板中心在 **相机坐标系** 下的三维位置（PnP 解算，单位 mm）；
3. **每帧处理时间**，以及整段视频的检出率统计；
4. 一个四状态跟踪器，短暂丢帧时用卡尔曼外推保持画面稳定（不闪）。

## 5. 构建与运行

```bash
cd aim2027
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

```bash
# 整段视频，窗口显示
./build/aim2027 assets/video1.avi

# 单帧详细结果（打印角点、位置、姿态、重投影误差）
./build/aim2027 assets/video1.avi --frame 300

# 左右分屏对比：左=逐帧实测（不跟踪） 右=跟踪结果
./build/aim2027 assets/video1.avi --compare --scale 0.5 --out-fps 30 --save out/cmp.mp4 --no-show

# 关掉跟踪，只统计逐帧检测
./build/aim2027 assets/video1.avi --no-tracker
```

| 选项 | 作用 |
|---|---|
| `--frame N` | 只处理第 N 帧，打印灯条/候选/角点/位姿/耗时 |
| `--limit N` | 只处理前 N 帧 |
| `--save 路径` | 写结果视频；`--out-fps` 指定帧率，`--scale` 缩放 |
| `--compare` | 左右分屏（左：逐帧实测，右：跟踪） |
| `--no-tracker` | 关掉跟踪，用于"上跟踪前/后"对比 |
| `--mask or|and|diff` | 颜色掩膜方式 |
| `--debug` | 叠加灯条框、候选框、掩膜缩略图 |
| `--no-show` / `--quiet` | 无界面 / 不打印进度 |

## 6. 算法流程与参数来源

### 6.1 流程

```
读帧
 └─ 颜色掩膜：HSV 红色两段 ∪ (R − max(G,B) > 40)
     └─ 形态学：开 3×3 去噪 → 闭 3×9 连断条
         └─ findContours → 每个轮廓求 minAreaRect
             └─ 灯条筛选：长宽比 / 长度 / 面积 / 倾角 / 红纯度(R-G, R-B)
                 └─ 两两配对：长度差 / 中心距比 / 连线斜率 / 平行度
                     └─ 每对 solver：solvePnP(IPPE) → 重投影 / 距离 / 角度 三重裁决
                         └─ 取重投影误差最小的那块
                             └─ 跟踪器：状态机 + 卡尔曼外推
                                 └─ 绘制 + HUD
```

### 6.2 关键判据都是实测出来的

| 判据 | 取值 | 依据 |
|---|---|---|
| 灯条红纯度 R−G | ≥ 55 | 真灯条实测 64~73，窗外暖白光带 43 |
| 灯条红纯度 R−B | ≥ 60 | 真灯条实测 74~128 |
| 灯条长宽比 | ≥ 1.5 | 与 `source_demo.yaml` 的 `min_lightbar_ratio` 一致 |
| 灯条倾角 | ≤ 45° | 与 `source_demo.yaml` 的 `max_angle_error` 一致 |
| 配对长度差 | ≤ 0.35 | 同板两灯条长度应接近；实测剔除掉跨机器人的错配 |
| 配对中心距比 | 0.8 ~ 4.5 | 装甲板宽/灯条长的物理范围 |
| **PnP 重投影** | **≤ 6.0 px** | 见下方说明 |
| 距离 | 0.5 ~ 3.5 m | 考核场景范围 |
| yaw / pitch | ≤ 70° / ≤ 45° | 超出时四点顺序会翻转，解不稳 |
| 跟踪确认 / 保持 | 5 帧 / 15 帧 | 直接取 `source_demo.yaml` 的 `min_detect_count` / `max_temp_lost_count` |
| 卡尔曼新息门限 | 马氏距离² ≤ 40 | 按实测位置噪声 σ≈50 mm 标定 |

**重投影门槛为什么是 6 而不是 2：** 板子转到侧面时，一根灯条会被挡住一截、
或被数字的光晕粘连，四点就不再是"127×50 刚性板"的精确投影，真板的重投影会到 3~6 px。
卡 2 px 的实测结果是 **video1 检出率只有 67 %**；放到 6 px 后 **92.49 %**。
放宽后混进来的错配解，由下面两道闸拦住（选候选时用上一帧位置做先验 + 卡尔曼新息检验）。

**装甲板尺寸**：角点取在灯条外缘，故

- 半宽 63.5 mm（外缘间距 127 mm）
- 半高 25.0 mm（灯条可见发光长度 50 mm）

交叉验证：第 300 帧像素四边形的宽高比为 `173 / 67 = 2.58`，`127 / 50 = 2.54` 吻合；
若按标称 `135 / 55 = 2.45` 则与实测不符，因此高度取 50 mm。

### 6.3 跟踪状态机

```
lost ──检出──> detecting（计数 +1）──连续 5 帧──> tracking
                  │                                  │
               中途断了 ──> lost            本帧没检出 ──> temp_lost
                                                     │
                                          丢 > 15 帧 ──> lost
```

- `tracking` / `temp_lost` 期间用 6 状态卡尔曼（`xyz + vxvyvz`，匀速模型）外推位置，
  再把 3D 位姿反投影回图像画**橙色虚线预测框**；
- 外推跑出 0.5~3.5 m 范围立即判丢失（发散保护）；
- 实测框是**绿色实线**，预测框是**橙色虚线**，一眼能分清画的是"看到的"还是"算出来的"；
- **确认之前不画框**：还没连续检出 5 帧时一个框都不显示，避免第一帧就是错配解时凭空画出一个偏一两米的框。

### 6.4 两道"防错配"的闸

重投影门槛放宽到 6 px 后，错配的灯条对（两个不相干的亮条）也能通过几何检查。
所以还有两道闸：

1. **选候选时用上一帧位置做先验**：打分从 `重投影` 改成 `重投影 + 0.004 × 离上一帧的距离(mm)`，
   即 250 mm 折合 1 px。错配解的位姿通常偏一两米，这一项会把它压到真板后面。
2. **卡尔曼新息检验**：测量与预测的马氏距离平方超过 40 就判为离群、不用于修正，继续用预测框。
   门限按实测位置噪声 σ≈50 mm 标定（卡方 0.999 的 16.27 会把一半真实测量也拦掉）。

## 8. 每段代码在做什么

| 文件 | 职责 |
|---|---|
| `include/config.hpp` | 全部参数（相机内参、板尺寸、筛选阈值、跟踪参数） |
| `include/types.hpp` | `LightBar`（灯条）/ `Armor`（装甲板）/ `Pose`（位姿） |
| `src/color.cpp` | 生成红色发光区域掩膜：HSV 两段 ∪ 通道差 |
| `src/detector.cpp` | 轮廓 → 灯条筛选 → 两两配对 → 候选按粗筛分排序 |
| `src/solver.cpp` | IPPE 解 PnP，双解择一，重投影/距离/角度三重自检 |
| `src/tracker.cpp` | 四状态机 + 卡尔曼外推 + 发散保护 |
| `src/draw.cpp` | 画框、四色角点、中心十字、HUD、调试叠加 |
| `src/main.cpp` | 参数解析、单帧/整段两条路径、统计输出 |

## 9. 已知限制

1. **只做红色**。蓝色没做——考核要求是"检测指定颜色（红蓝色）的装甲板"，两段考核视频里的目标都是红方；蓝方只需要把 `buildRedMask` 的 H 段和 `R−max(G,B)` 换成 `B−max(R,G)`，其余全部复用。
2. **装甲板尺寸按外缘 127 mm × 发光区 50 mm 标定**。若按 RM 标称的 135 mm 板宽计算，距离绝对值会偏小约 6 %，但同一段视频内部的相对变化不受影响。
3. **左右倾斜超过约 45°** 时四个角点的顺序会翻转，PnP 解会跳；本项目靠重投影误差把这种解剔除（表现为丢检，不会给出错位置）。
4. **yaw / pitch 有共面四点的镜像歧义**。4 个点解平面位姿，IPPE 会给出两个重投影几乎一样好的解，
   姿态角可能差十几度。本项目用「帧间连续性」锁定同一支路（`solvePose` 的 `rvecHint`），
   静止目标上读数已经稳定；但**角度绝对值受相机安装角影响**，正视装甲板时读数不为 0，
   它表示"相机系下板面的倾角"，不是板子相对地面的倾角。**位置（xyz）不受这个歧义影响**，两个解算出的距离差 < 0.1 %。
5. 窗外暖白光带靠红纯度（R−G ≥ 55）剔除，若现场换成更偏橙的光源需要重标。
6. 处理时间在虚拟机里有 1.5~2 倍波动，真实耗时以实车/裸机为准。
7. **放宽重投影门槛的代价**：video1 上有 526 帧（30 %）的测量被卡尔曼新息检验判为离群，
   说明"错配的灯条对"仍是主要噪声源。根治办法是单灯条外推（只用一根灯条 + 历史位姿
   还原另一根），本项目未实现。
8. **个别帧位置仍会跳**：video1 最大相邻帧跳变 569 mm（90 % 分位是 30 mm，中位 3.7 mm）。
   跳的那几帧都是旋转到极限、只剩一根灯条可见的时刻。
