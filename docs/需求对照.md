# 需求对照

把考核任务逐条对到实现位置。凡是没做到的，第 4 节如实列出来。

## 1. 基础任务

| 考核要求 | 实现方式 | 代码位置 |
|---|---|---|
| 检测指定颜色（红蓝色）的装甲板 | 颜色分割：HSV 红色两段 `[0,12]`/`[165,180]` 与通道差 `R−max(G,B)>40` 取并集，再开运算 3×3、闭运算 3×9 | `src/color.cpp: buildRedMask` |
| | 轮廓 → 最小外接旋转矩形 → 五条筛选（长宽比、长度、面积、倾角、红纯度 R−G/R−B） | `src/detector.cpp: buildBar`、`setBarGeometry`、`measurePurity` |
| | 灯条两两配对：长度差 ≤35%、中心距比 ∈[0.8,4.5]、连线斜率 ≤0.35、倾角差 ≤20° | `src/detector.cpp: detect` |
| **标出四个角点** | 每根灯条取朝外那条长边的两个端点，按 左上/右上/右下/左下 排列；画成绿色四边形 + 四个彩色角点 | `src/detector.cpp: outerEdge`（求点）、`src/draw.cpp: drawPlate`（绘制） |
| **标出中心点** | 四个角点的均值，画白色十字 | `src/draw.cpp: drawPlate` |
| **估计中心在相机坐标系的三维位置** | `solvePnP(SOLVEPNP_IPPE)`：已知板坐标系四点 `(±67.5, ±28, 0)` mm、像素四点、相机内参，求旋转与平移；平移向量即板心在相机系的位置 | `src/solver.cpp: solvePose`、`objectPoints` |
| | 解的自检：重投影 ≤6 px、距离 ∈[0.5,3.5] m、\|yaw\|≤70°、\|pitch\|≤45° | `src/solver.cpp: solvePose` |
| **显示检测结果** | 绿色实线框 + 四色角点（实测）、橙色虚线框（跟踪器预测） | `src/draw.cpp: drawPlate` |
| **显示三维位置** | HUD 第二行 `XYZ(mm) x y z  DIST d` | `src/draw.cpp: drawHud` |
| **显示处理耗时** | 每帧 `getTickCount` 计时，HUD 第四行 `TIME xx ms`；汇总另给平均/中位 | `src/main.cpp`（计时）、`src/draw.cpp: drawHud` |

## 2. 数据与接口要求

| 要求 | 实现方式 | 代码位置 |
|---|---|---|
| **相机参数**：使用与输入视频同一数据包的内参文件 | `--camera <path>` 读 `calibration/intrinsics.yaml`，解析其中的 `camera_matrix`（9 个数）与 `distort_coeffs`（5 个数）；文件是普通 YAML，手写解析，不引入新依赖 | `src/main.cpp: loadCamera` |
| 内参真正参与求解 | 相机矩阵与畸变系数同时用于 PnP 和反投影 | `src/solver.cpp: cameraMatrix`、`distCoeffs` |
| **小装甲板尺寸 135 mm × 56 mm，高度取灯条长度** | 半宽 67.5 mm、半高 28.0 mm | `include/config.hpp: kHalfW / kHalfH` |
| **输入视频** | 第一个位置参数 | `src/main.cpp: parseArgs` |
| **输出路径** | `--save <路径>`，画上结果写成视频 | `src/main.cpp`（VideoWriter） |
| **目标颜色** | 固定红色；`--mask or/and/diff` 只调掩膜组合方式，不切换颜色 | `src/main.cpp: parseArgs` + `src/color.cpp` |

## 3. 环境要求

| 考核要求 | 落实情况 |
|---|---|
| Ubuntu 22.04 | 开发与验证环境，实测通过 |
| 开发语言 C++ | 全部源码 C++17，无脚本依赖（`scripts/regression.sh` 仅用于回归统计） |
| 补充编译器版本与 C++ 标准 | g++ 11.4.0 / C++17，见 `README.md` 第 1 节 |
| 补充依赖名称、版本和安装命令 | OpenCV 4.5.4，`sudo apt install -y build-essential cmake libopencv-dev`，见 `README.md` 第 1 节 |
| 模型文件（若使用） | **不使用任何模型**，纯传统视觉 |

## 4. 偏离与未实现

| 项 | 现状 | 说明 |
|---|---|---|
| **蓝色装甲板** | 未实现 | 两段考核视频中的目标均为红方。扩展只需把 `buildRedMask` 的 H 段与通道差从 `R−max(G,B)` 改成 `B−max(R,G)`，下游全部复用 |
| IMU / 手眼数据 | 未使用 | 任务只要求"装甲板中心在**相机坐标系**下的三维位置"，不需要转到云台系或世界系 |
| 数字识别 | 未实现 | 非考核项。配对阶段用了一个板面明暗对比度辅助判断（`src/detector.cpp: boardNumberContrast`），不是数字分类 |
| 单灯条外推 | 部分实现 | 灯条一端被遮挡时会把端点外推补齐（`src/detector.cpp: extrapolatePartialEndpoint`），但"只剩一根灯条可见"时仍只能靠跟踪器保持 |

## 5. 怎么自查

```bash
# 构建
cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j$(nproc)

# 单帧：看四个角点、中心、位置、耗时
./build/aim2027 data/<数据包>/video/video.avi --frame 300

# 整段：出结果视频
./build/aim2027 data/<数据包>/video/video.avi \
  --camera data/<数据包>/calibration/intrinsics.yaml \
  --save out/result.mp4

# 回归统计（两段视频的可量化指标）
bash scripts/regression.sh
```
